# 交互画图合理性口径（决策文档）

范围：本文只回答一个问题——**什么情况下给学生挂交互画图（动态画板）才是合理的**。适用于 `diagnose/funclab.js` 一系动态画板，以及未来几何类交互。
不覆盖：怎么画（渲染实现见 `docs/funclab-coverage.md` / `docs/highschool-funclab-coverage.md`）、覆盖率测算（见 `scripts/measure_*_coverage.js`）。

口径来源：板主与用户 2026-11-05 裁定。核心判据原文：「图的目的是让学生能够更好地理解问题是怎么解决的，不是看到答案」。

## 0. 一句话判据

**交互只在「学生的操作能揭示一种关系，而这个关系是他自己推出来的」时才合理。**

把答案摆到图上 = 泄题；图上根本没有答案 = 装饰。两者都不该做交互。

推论：先有确定性渲染器（参数 → 图元 → 断言），才有交互。交互不是渲染的替代品，是渲染之上多出来的一层「因果可见性」。

## 1. 三条必要条件（闸门，缺一不可）

### 闸门一：答案必须是图上的量，或由图上量的变化可推

这是最硬的一条，也是历史代价换来的。

- 正例 `cnm_h029_q2`（f(x)=−x² 的最大值）：答案 0 就是顶点纵坐标，图上直接读
- 正例 `cnm_h034_q3`（f(x)=−(x−1)²+5 的最大值）：答案 5 是顶点纵坐标
- 正例 `cnm_225_q2`（(x+1)²=16 的两根）：答案 3、−5 是两处零点的横坐标（前提：解析正确，见闸门三）
- 反例 `cnm_h220_q2`（y=x² 在 x=0 处的切线斜率）：画板上的「0」是函数值，不是斜率——数字相等不等于语义对上
- 反例 R2 口径：只按题面解析放宽，195 题里 163 题误挂（答案多为判别式、面积、参数范围），图上根本没有这些量

判据怎么用：拿到题先问「这道题的答案，学生在图上指得出来吗？」指不出来就不挂，无论题面多像函数题。

### 闸门二：可变维度必须由题面确定，且不超过 1–2 个

交互的价值来自「看见参数的作用」：拖 a 看开口，拖 ω 看周期，拖 φ 看平移，拖 h/k 看顶点。前提是题面给出参数化形态。

- 可做：`y=a(x−h)²+k`、`y=A·sin(ωx+φ)+k`、`y=log_a x`——参数少、含义明确、变化可预期
- 不可做：带参数讨论题（「讨论 a 的取值对零点个数的影响」）、抽象函数题（「已知 f 是奇函数」）。图只能表示一个特例，学生会把特例当一般结论
- 这两类正是 `docs/highschool-funclab-coverage.md` 中单列「带参数母题」「抽象函数」的原因，属永久排除族

### 闸门三：图上每个数字都必须从题面确定性算出，并能自动断言

图错比无图更伤人。顺序必须是「题干 → 结构化已知量 → 图元库渲染 → 断言图上标的值 == 题面值」。LLM 只允许产出参数 JSON，**不许直接产出 SVG 坐标**。

- 已落地：`scripts/fig_draw.py` + `scripts/add_figures.py` 的 `expect()/near()` 断言；`labFor` + 答案语义门禁
- 已知反例 `cnm_225_q4`（(2x-3)²=(x+1)²）：解析器把左边 (2x-3)² 整个丢掉，得 `a=1,h=-1,k=0`，真解是 `3x²−14x+8`。这类「等式两边都是完全平方」的解析歧义未修之前，同形态题一律不放行
- 图上标注规则：只标已知量；派生量一律 `?`；学生点「我算好了」才显示对比

## 2. 五档交互用途（能做的，按价值排序）

每档都要先说清「学生操作后，看见的到底是什么」。

1. **参数探索（滑块驱动 a/ω/φ/h/k）**——适合「参数如何影响图形」：单调性、周期、开口、平移。交互不可替代：静态图给结论，交互图给因果。
2. **读数（点关键点、显示坐标）**——适合「答案就在图上」：零点、顶点、交点、定义域边界、渐近线。
3. **对比（同屏原曲线 vs 目标曲线）**——适合变换、不等式、方程根的个数比较。
4. **动态过程（动点轨迹、极限、变化率）**——适合轨迹与瞬时变化；风险是「看动画代替推理」，必须配提问。
5. **构造/作图（拖点、作辅助线）**——适合几何作图与辅助线思路，成本与验证风险最高，排最后。

失败模式统一是同一件事：**操作没有产生新的可见后果**。拖完和拖前看到的是同一件事，那是动画，不是交互。

## 3. 四类不该画（负面清单）

1. **概念判断、方法选择**：`cnm_225_q1`（3x²=6x 选用什么方法）、`cnm_225_q3`（最适合直接开平方法的是哪个）、`cnm_h034_q4`（闭区间上连续函数最值在哪取到）——答案是「哪种方法/哪个结论」，图上没有这个量
2. **纯代数变形与计算**：图是冗余，还拉长解题路径
3. **抽象函数、带参讨论**：图无法代表全体（见闸门二）
4. **条件含「任意 / 至少 / 恒成立」**：一张图只是一个实例，学生极易把实例当证明

## 4. 两条附加判据

- **交互成本必须低于认知收益**：手机上要精准点中滑块、要横屏、要等重绘，学生很可能只是在玩。这种情况下静态图 + 一句「看这里」更诚实。交互图若还要求滚动去找控件，收益为负
- **先预测再验证（guess-then-check）**：让学生拖动之前先猜「a 变大，开口变宽还是变窄」，再拖。这是交互图区别于静态图的真正长处；没有预测这一步，交互图只是能动的插图

## 5. 落到本项目的排序结论

1. **先做解析/渲染骨架能覆盖多题的族**（指数 / 对数 / 幂根式）：一个骨架覆盖多题、答案多为渐近线/定点/单调区间，三条闸门都满足
2. **再做参数探索型交互**：这是交互唯一不可替代的能力，应作为独立设计，而不是塞进「能挂多少题」的框架
3. **几何构造类交互最后做**：成本与验证风险最高
4. **方法选择章（如 `cnm_225`）不做交互**：最多补一张静态示意图，且同样要过闸门一

## 6. 新卡验收前置检查表

任何新增画板/交互的卡，验收前先答这三问，答不上就不许挂：

- [ ] 这道题的答案，学生在图上指得出来吗？
- [ ] 可变维度是哪些？是否由题面唯一确定、不超过 2 个？
- [ ] 图上每个数字都能从题面确定性算出并断言吗？错一个数字会怎样？

## 8. 选择题要几张图

判据不看选项个数，看**答案是什么形态**。

| 答案形态 | 图数 | 画什么 |
| --- | --- | --- |
| 数值（最值/周期/零点/交点个数） | 1 | 题面那个函数 |
| 性质判断（单调/奇偶/定义域） | 1 | 题面那个函数 +（可选）不变量标注 |
| 选哪个函数符合某性质（对比型） | 1（多曲线） | 同坐标系，最多 2 条 |
| 求解析式（选项是 4 个式子） | 1 | 只画「由条件唯一确定的那条」 |
| 选项本身是图形 | 0 | 静态 SVG（`figure` 字段），不给画板 |
| 选方法 / 选概念 | 0 | 图与答案无关 |

**硬规则：不许把全部选项都画出来。** 那等于把答案并排摆开让学生挑，正好违反本文第 0 节判据。反求型尤其要守住——例：选项给 `y=6/x`、`y=−3/(2x)`、`y=−2/(3x)`、`y=−6/x` 时，正确做法是画「过题面定点的那条反比例曲线」，让学生自己算出 k 再对选项；四条都画，看图比形状就能猜。

对比型的落地约束（真要做时）：

- 一屏一张板，最多 2 条曲线（现有 `curves` 板即两条）；超过 2 条手机上分不清颜色
- 4 个候选拆两张（先 A/B 再 C/D），必须同坐标系同刻度，否则对比本身是错的
- 候选用 ①②③④ 而非 A/B/C/D 标注，避免学生直接读「哪个像答案」

本轮实测量级（一次性统计，脚本未入库；复核方式：对 `data/questions.json` 用 `node -e` 按 `q.type==='choice'`、`/图象|图像/.test(q.prompt)`、选项 `^y=|[f(x)]=` 过滤）：选择题 9268 题，题干提到「图象/图像」27 题，其中 ≥2 个选项是 `y=`/`f(x)=` 形式的仅 3 题，选项自带 `figure` 的 13 题。**「多函数需要多图」在当前题库不是瓶颈**，别为它提前扩渲染能力。

## 9. 追问不做自由图：函数身份锁定，参数可探索

单曲线板代表**本题题面**的参数。允许追问把它换成 cos / tan，会同时坏两件事：学生点「回到题目参数」时不知道该回到哪条曲线；sin 与 cos 形状相同、教学收益为零而误导成本很高。

- **函数身份锁定**：追问可以带图，但图必须是本题这个函数——`type` / `lab` / `fn` 与题面画板一致，**只允许参数值变化**
- **参数可探索**：拖 A/ω/φ/k、a/h/k、k/b 仍然全部保留。限制的是身份，不是滑块
- **不变量必须可见**：拖动后要显式标出「什么没变」（周期没变 / 波峰高度没变 / 对称轴没动 / 渐近线没动）。学生拖完只看到数字变，等于动画而非交互
- **偏离状态可见**：参数被拖到与题面不同时，画板区显示「当前已偏离题目参数」，复位按钮高亮
- **要么画，要么不说**：`graph` 是否存在是布尔事实。`graph` 为空或被拒时，由**系统**陈述「本次回答没有配图；画板仍是本题的 y=…」，公式从当前画板配置生成，不手写；模型正文只进对话气泡，不进画板卡片
- **不做字符串兜底**：不许用「指图短语黑名单」或按函数名删句来判断模型是否在乱说——这既违反「无正则保底」，也无法预知模型措辞。靠结构化字段 + 系统陈述 + 渲染隔离
- **对比板另做**：未来若做多曲线，只画**题面点名出现过的函数**，并标「示意图」；不因一句错误的话去放开 `fn` 枚举
