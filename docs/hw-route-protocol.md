# 外部分析文字 → 知识点定位 → 学习路径

## 输入协议（全部字段可选）

外部 app 对本项目的输入是一段**自然语言分析文字**。本项目不假设它一定包含哪些字段，而是**尽量解析，解析不出的走降级**。

推荐外部 app 输出（按下表优先级，越靠前价值越大）：

| 字段 | 价值 | 缺失后果 |
|---|---|---|
| 年级 / 学段 | ★★★ | 候选池 802 个，命中率大幅下降 |
| 领域（数与代数/图形与几何/统计与概率/综合与实践） | ★★★ | 同上 |
| 章节名 | ★★ | 候选池从 ~12 缩到 ~2 |
| 考点描述（用自己的话说这题考什么） | ★★ | LLM 少了最重要的语义锚点 |
| 是否含图形 / 图形类型 | ★ | 几何题定位准确率下降 |
| 解题步骤数、关键条件 | ★ | 定位精度下降 |
| 学生答案 / 卡在哪一步 | ★ | **仅影响「错误类型分析」，不影响知识点定位与路径** |

**本项目不假定字段顺序、不假设有结构化格式。** 一段纯文字（如「这是一道初三数学题，考查用配方法解一元二次方程，学生算到一半卡住了」）就应当能工作。

## 降级阶梯

```
解析出 年级 + 领域            → 候选 ~12 个（年级精确）
解析出 学段 + 领域            → 候选 ~50-140 个
解析出 领域                  → 候选 ~150-400 个
什么都解析不出                → 明确告知「信息不足，请补充年级」，不猜
```

**最后一步是硬规则：猜不出来就说猜不出来。** 宁可让学生补一句年级，也不能给一个可能完全错的知识点——学生会照着复习一小时，白费。

## 处理后链路

```
文字
 ↓ ① parseFields()        正则 + 关键词，抽年级/领域/章节/考点描述
 ↓ ② candidates()         按解析出的字段筛候选池（纯确定性，无 LLM）
 ↓ ③ LLM 在候选池内选 1-3 个 + 置信度 + 理由
 ↓ ④ verifyPick()         确定性校验：选中项必须在候选池内；考点描述的关键词
 ↓                        必须能在该知识点的 name/description/mastery_criteria 里找到
 ↓                        校验不过 → 拒绝，不硬套
 ↓ ⑤ 学生确认            3 个候选让学生点，不自作聪明只给一个
 ↓ ⑥ prerequisites()      沿 hard 边回溯 2 层
 ↓ ⑦ 输出路径             第一版：标注为「候选薄弱点，待测确认」，不假装已诊断
```

## 第一版明确不做

- **不做拍照 / OCR**（外部 app 负责）
- **不做「测前置」的自动判定**（需要学生答题数据；第一版只给候选并标注「待测」）
- **不做错误类型分析**（需要学生答案，第一版不依赖）
- **不改现有 diagnose 的任何逻辑**（画板、讲解、题库判定一律不碰）
- **不做学生历史/掌握度**（没有数据来源）

## 数据事实（实测，用于设计候选池）

```
知识点总数 1503，其中数学 802、英语 701
数学按学段：小学 216 / 初中 315 / 高中 271
数学按学段+领域：最大区间 142（小学数与代数），最小区间 5（高中综合与实践）
数学按年级：1-12 + 13-16（13-16 是高中延伸）
章节数 301，每章节知识点数中位数 2  ← 章节是极强的筛子
依赖边 2176（hard 1323 / soft 853），无断链、无环
每知识点有 4-5 道题（共 6159 道）
每个知识点都有 description / mastery_criteria / diagnostic_question
```

## 已知的坑

1. **英语知识点（701 个）混在同一个库里**，id 前缀 `cne`，必须按前缀或 `subject` 字段排除。
2. **「知识点名关键词出现在题面」的覆盖率只有 3%**（实测前 500 题），所以 **绝对不能做关键词匹配定位**。
3. **年级字段 13-16 是高中**，不是大学；1-12 对应小学一年级到高三。
4. **依赖图有软边噪音**：`垂径定理` 的 3 层 soft 前置里有「有理数的加减混合运算」「线段的比较与运算」。路径生成**只用 hard 边**，soft 边只作为「可选补充」提示，不能进主路径。
5. **依赖图不是诊断结果**：`配方法` 的前置里有三年级「长方形和正方形的面积」。图告诉你结构，不告诉你哪里断了。
6. **verifyParams 式硬拒绝**：LLM 选的必须能对上知识点描述里的词，不能只凭「感觉像」。

## 实现（第一版，已落地）

页面：`diagnose/route.html`（独立入口，不碰 `diagnose/index.html` 和任何现有 diagnose 逻辑）。

| 文件 | 职责 |
|---|---|

| `diagnose/route.html` / `route.css` | 六段输出区（① 字段 ② 候选池 ③ LLM 选择 ④ 校验 ⑤ 前置链 ⑥ 路径） |

### 与上面协议的差异（实测后调整，均为收紧）

1. **候选池实际规模**：`初三 + 数与代数` 单独筛是 **24** 个；`parseFields` 从「用配方法解一元二次方程」里认出章节标题「一元二次方程」后收窄到 **9** 个。章节筛子只在**已解析出年级**时启用——只有领域时 2 字章节标题（「函数」「相似」「旋转」）撞车概率太高，会把 401 缩到个位数，召回风险不值当。
2. **高三 → 年级集合 {12,13,14}**：库里 12/13/14 是选择性必修三册，高三学生实际在学这三年级的点，所以按集合筛，不按单值。
3. **章节标题匹配优先于「第X章」编号**：同一编号在不同年级重复（第五章在七上是「一元一次方程」、在高一是「三角函数」），编号不可靠；标题匹配更具体。2 字标题要求词边界，避免「二次函数」命中八下的「函数」。
4. **非数学文字直接拒绝**：识别到语文/英语/物理等学科词且**没有任何数学领域线索**时，页面显示「拒绝定位：这段文字不是数学题」，不进候选池流程（验收 5）。
5. **主路径的跨学段过滤比协议多一条**：协议里只写了「soft + 年级差 ≥ 4 年」过滤；实测 `垂径定理` 的 **hard** 链里也有四年级「轴对称」，所以主路径额外加了一条硬规则——目标在初中/高中时，小学（≤6 年级）前置一律不进主路径，只在「已过滤（噪音）」里列出并说明原因。目标本身是小学时不过滤。

### 校验规则（确定性，LLM 绕不过去）

| 规则 | 判据 | 不过的后果 |
|---|---|---|
| 规则1 | 选中 id 必须在本次候选池内 | 拒绝该选择 |
| 规则2 | 知识点名必须与库里该 id 的名字逐字一致 | 拒绝该选择（按编造处理） |
| 规则3 | 考点描述的 2~4 字 n-gram 必须能在该知识点 `name`/`description`/`mastery_criteria` 里找到对应：覆盖率 = 0 → 拒绝；0 < 覆盖率 < 18% → 置信度 ×0.6 并标注；未解析出考点描述 → 置信度 ×0.7 并标注「语义未核对」 | 拒绝 / 降置信度 |

所有选择都被拒 → 页面显示「分析结果无法定位到知识点」+ 逐条拒绝理由，不给前置链、不给路径。

### 页面状态机

`insufficient`（信息不足，①② 之后停） / `not-math`（拒绝定位） / `await-llm` → `verified`（③④⑤⑥ 全出） 或 `rejected`（④ 拒绝，⑤⑥ 跳过） 或 `offline`（③ 没跑起来：①② 照常显示，③ 给明确提示，⑤⑥ 说明为什么不给）。

**①② 永远是纯确定性结果，网关挂掉也照常显示**（验收 7）。
