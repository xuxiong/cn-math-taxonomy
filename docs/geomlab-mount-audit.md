# geomlab 实际挂载率验证（H 卡）

> 数据：`data/questions.json` 6159 题 / `data/topics.json` 1503 个知识点。全文所有数字由 `node scripts/verify_geomlab_mounts.js` 一条命令产出，附录 A 是该脚本 stdout 全文；正文与附录同源，因此**逐字一致**。

## 结论先行

- **圆的 42 题预测，实际挂载 11 题。** 题池 113 题的全部去向：实际挂载 11 + 门禁挡掉 44 + 解析失败 58 = 113（题池闭合）。比 F 预测 42 题少 31 题：F 的 42 是「题面条件够画」的理论上限，画板实际还要过答案语义门禁（44 题被挡，主要是纯算式/问个数/判断辨析）与六骨架解析（58 题认不出，主要是条件不足、弧长扇形、圆内接四边形/外心内心）。
- **相似类不做第二批。** 实际挂载 3 题（F 预测 14），远低于 F 卡自己给的「≥10 才值得立项」门槛；且门禁挡 10 题、解析失败 23 题，转化率仅 8.3%。挂载题的形态：纯比例计算 1 题、含几何位置关系 2 题（明细见第六章）。
- 全库白名单三类（circle/similar/triangle）共 288 题，实际挂载 16 题，占总题池 5.6%。

## 方法

1. **逐题调用与线上逐字一致**：`diagnose/app.js` 第 3 步 analyst 回退分支调用`Geomlab.labFor(t && t.id, q && q.prompt, {itemId: q && q.id, topic: t, answer: q && q.answer, choices: q && q.choices})`；本脚本原样照抄，不补 answer、不传默认值 —— 缺参时的 fail-closed 本身就是被测对象。
2. **三类 = `Geomlab.classOf(topicId, {topic})` 认得的结果**，其余计入「非白名单」。不另外造一套分类，避免与画板自身口径打架。
3. **挡下原因**用 `Geomlab.gate(prompt, {itemId, answer, choices})` 同参复算（该调用只读、幂等，不改变 labFor 的判定）；`gate` 不挡而 `labFor` 返回 null 的，记为**解析失败**——那是真正的覆盖缺口。
4. **解析失败成因归类**只用题面可见特征的正则（本脚本内 `FILLER_RULES`），顺序即优先级；这一步只解释「这张图该不该存在」，不参与挂载判定。
5. **抽样确定性**：按 itemId 升序后等距取样（`floor(i × N / k)`），不随机、不读系统时间，两次运行 stdout 逐字相同。
6. **全程无 LLM**：所有判定来自画板自身的正则/骨架解析与 `solve()`。

### 2.1 题池口径差异（F 卡 vs 画板 classOf）

| 类 | 画板题池 | F 题池 | 差额 | 差额题目 |

差额成因：`classOf()` 是 `classOfTopic(topic) || classOfId(topicId)` —— 章名判为「三维体」时返回 null，但随后又退回 id 段，把 `cnm_258`（圆锥的侧面积）判成 circle。F 卡脚本对三维体是硬剔除。这是**既有行为的差异，本卡未改判定口径**；上述题全部落在第四章「解析失败」里（六个骨架本就不画圆锥），因此不影响实际挂载数，只影响题池分母。

注：F 的「保守覆盖」是**理论上限**（题面条件是否够画），本表「实际挂载」是**画板真的挂上了**。两者口径不同：F 只要求题面条件够画，实际挂载还要过答案语义门禁、还要能被六个骨架之一解析。因此「实际挂载 < F 预测」不必然是退步，而「实际挂载 > F 预测」说明 F 低估了可挂题（多为门禁未挡的薄覆盖题）。
