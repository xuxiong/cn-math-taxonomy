## 结论摘要

1. **现状基线 58 题**（占全库 0.9%，占 29 个白名单知识点下 120 题的 48.3%），覆盖 20 个知识点。
2. **R1（只放宽方程章白名单）几乎零收益**：61 题，新增 3 题，而这 3 题全部是误挂（配方常数、判别式、根的情况）；**净增 0 题**。卡面假设「章级白名单是覆盖率首要瓶颈」不成立——章级白名单只挡下 3 题，且恰好都是该挡的。
3. **真正的瓶颈是 `fromPrompt` 解析能力**：支持章节内被挡的 62 题里，54 题（87%）根本解析不出函数（`y=kx+b` 字母系数的概念题、过点求解析式、应用题建模等）。
4. **R2（全库按题面解析）净增只有 4 题**：195 题能解析出函数，但 163 题（83.6%）的答案与函数图像无关（代数式、判别式、参数范围、面积、导数…）；剩下 31 题里 27 题与基线重合，**真正净增 4 题**，同时会丢掉基线 31 题——作为「替换白名单」的方案是负收益。
5. **建议采 R3**：白名单不动，只把 4 个知识点（`cnm_225`、`cnm_267`、`cnm_h029`、`cnm_h034`）补进 `topicKind`，并对新准入的题加答案语义门禁 → **62 题，误挂 0**。详见第五节。

## 四、误挂风险清单

判定方式（三道，逐题对 answer 字段，不看题面关键词就下结论）：
  ① 把答案里的数值抽出来（选择题先按 choices 展开成选项原文；分数 3/4 折成小数；坐标对 (a,b) 按分量比）
  ② 与画板在该函数上**真实标注**的数逐个比对：二次 = 顶点 (h,k) + x 轴交点；一次 = y 轴截距 (0,b) + x 轴交点；
     反比例 = 无数值标注（只有象限说明文字）；任一数值对不上 → 判误挂
  ③ 数值全对上但题面问的是图外量（判别式/范围/有几个交点/形态 m、n/面积/导数…）→ 降级 suspect；
     再由人工逐条定档（结论写死在脚本 MANUAL_REVIEW 表里，报告里的数字因此仍可复现）

门禁自校准（同一套判定套到基线 58 题上，用来衡量它有多严）：

| 基线 58 题在门禁下的判定 | 题数 |
| --- | --- |
| ok | 27 |
| suspect | 0 |
| misleading | 31 |

说明：门禁挡住了基线里 31 题，其中约 6 题属于「象限/增减性/交点个数」这类
纯图像可读、但画板没有数值标注的答案 —— 门禁判得过严，是**保守下限**，不是精确分类器。
因此下面各方案的「加门禁」数字都是**低估**，报告结论据此按保守方向取。

### 5.3 放行规则（写成可实现的判定条件）

判据按顺序短路，任一不满足即 `return null`（= 不挂画板，静默降级）：

```js
// ① 知识点必须命中白名单（保留现状，并且只补 4 个）
const kind = topicKind(topicId);              // 现实现 + 'cnm_225' | 'cnm_267' | 'cnm_h029' | 'cnm_h034'
if (!kind) return null;

// ② 题面必须解析出函数，且类型与知识点一致（现状不变）
const p = fromPrompt(prompt);
if (!p || p.type !== kind) return null;

// ③ 方程章（cnm_220..224）沿用现行逐题门禁（不放开）
//    EQUATION_FORM_LABEL / EQUATION_WORDS / hasCleanRoots 三道原样保留

// ④ 新增：答案语义门禁 —— 答案必须是画板真会标出来的量
const ann = boardAnnotations(p);              // 二次: {x:[h, h±√(-k/a)], y:[k,0], pairs:[顶点, 绿点]}
                                              // 一次: {x:[0, -b/k], y:[b, 0]}
                                              // 反比例: 无数值标注（只有象限说明文字）
const nums = answerNumbers(question);         // 选择题先用 choices[answer] 展开成选项原文，再抽数
if (nums.length === 0) return null;           // 纯文字答案（"是/不是"、代数式）不挂
for (const v of nums) {                       // 坐标对按分量比，单值按 x/y 任一方向比
  if (!inSet(ann.x, v) && !inSet(ann.y, v)) return null;
}
// ⑤ 数值对上了、但题面问的是图外量（判别式/范围/有几个交点/形态 m、n/面积/导数）→ 也不挂
if (asksOffGraphQuantity(prompt)) return null;
```

两条经验判据（都来自逐题核对 `answer` 字段，不是关键词猜测）：

- **数值重合 ≠ 相关**：`cnm_208_q2` 的答案 2 恰好等于所画直线的 y 截距，但题目问的是两条线的交点（画板只画一条）；`cnm_h050_q2` 的 0 是 `f(2)` 的函数值，画板却把 0 标成「方程的根」。所以第 ④ 步只能当**必要条件**，第 ⑤ 步必须同时生效。
- **多解要看题设筛选**：`cnm_156_q4` 画板给出 ±3 两个绿点，答案只要 +3（-3 因分母 `x+3` 被排除）——绿点全在图上，但会诱导学生答「±3」。这类题即便数值全中，也该由第 ⑤ 步的语义判断挡下。

### 5.4 `cnm_267_q2`（卡面已知案例）的真实拦截点

```
二次函数 y=-x^2+6x 的最大值是多少？  →  fromPrompt 解析出 {a:-1,h:3,k:9}，答案 9 = 顶点纵坐标 k
```

它在题库里挂在 `cnm_267`（综合与实践：生活中的优化问题），**实际拦截点是 `topicKind` 返回 null**，不是 `EQUATION_CHAPTERS`。
卡面说的「在 `cnm_221` 下返回 null」只有在把它挪到 `cnm_221` 时才成立（`CHAPTERS_ITEM_ONLY` 只放行 `cnm_221_q3`）。两种拦截的修法不同：前者要补白名单（R3 已含），后者要放开章级白名单（R1，实测净增 0，不建议）。

### 5.5 顺带发现（不在本卡范围，供后续排期）

- 门禁自校准显示**基线 58 题里有 31 题通不过同一套答案语义检查**，其中确实有同类问题：`cnm_208_q1`（两线交点，画板只画一条）、`cnm_204_q1`（平移后解析式）、`cnm_234_q2`（交点个数）。这批与本次放不放宽无关，但说明「绿点与答案无关」不是放宽才引入的问题，基线里就有存量。
- 其中约 6 题属于「象限/增减性/交点个数」这类**纯图像可读、但画板没有数值标注**的答案，被门禁判得过严。所以本文所有「加门禁」的数字都是**保守下限**。
