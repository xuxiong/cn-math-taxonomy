# 高中函数画板覆盖率测算（只读）

```
命令：node scripts/measure_highschool_funclab_coverage.js
分支：wt/hs-funclab-coverage（基点 main 7bac18a；建卡时写 b782bc5，两者之间 diagnose/、data/ 零改动）
性质：只读。不改 diagnose/、不改 data/、不补任何图；本文件 stdout 即 docs/highschool-funclab-coverage.md 全文。
```

三档口径（后文所有数字都落在这三档里，混用即误读）：

- **baseline** = `diagnose/funclab.js` 原样（`topicKind` 白名单 + `labFor` + `fromPrompt`），一行未改
- **literal** = 本脚本内联的候选解析器，能从题面解析出一条**参数全为数字**的确定曲线
- **gated** = literal 再要求「参考答案落在画板的标注语义里」（关键点、零点、最值、单调、周期、渐近线、定义域边界）

gated 档再细分四类（`extend`/`pair` 是「要新增一种能力才挂得上」，与「误挂」严格分开）：

- `ok` —— 现有标注语义就够，挂上即有用
- `extend` —— 同一条曲线，加一种标注（题干点 / 区间端点 / 定义域带 / 割线）
- `pair` —— 要两条曲线同屏（反函数、指对对称）
- `misleading` —— 挂了反而误导：答案不在图上，或图上标的不是答案（**这就是误挂风险**）

| 族 | 规则 | 解析出的参数 |
|---|---|---|

## 3. 加答案语义门禁（gated）：扣掉「图与答案无关」之后

门禁不是看答案里有没有图上的数，而是**逐题重算**：解析出的函数自己算零点/顶点/极值/周期/奇偶/定义域，再与参考答案比对。比对不上、或答案问的是图上没有的量（和差、参数、解析式），一律 `misleading`。

| misleading / needs-tangent-board |   21 | 要切线/导数值读数，属切线画板         |
| extend / needs-prompt-point      |   20 | 要新增"题干给定输入点"标注            |
| ok / monotonic-on-board          |    9 | 曲线走向即答案                        |

**Q3 哪些必须永久排除？**

- **带字母参数的母题**（8 题）：`y=ab^x`、`y=A sin(ωx+φ)`、`y=log_a x` —— 参数不给定，曲线形状不唯一，画出来就是编一个特例。

### 10.1 修法一：quadratic 补三类能力（含读数文案）

`diagnose/funclab.js` 的 `CAPABILITIES` / `CAP_TYPE` / `NOTE_INTENT` / `paintModel` / `draw` / `answerRows` 六处同改，
原则与批1.5 反比例定义域一致：**答案必须真能从图上读出来**，读不出来的不收。

| 问法 | 挂在哪块板 | 图上的读数对象 | 答案行 |
|------|------------|----------------|--------|
| 与 x 轴交点的个数 | `quadratic-roots`（`canAnswer` 加一项，不是新板） | 绿色圆点的**个数**（0/1/2 三态都画得出来：无交点时一个绿点都没有） | `scalar`，按判别式 −k/a 给 0/1/2 |
| 单调性 | 新板 `quadratic-monotonic`（`CAP_TYPE=quadratic`） | 曲线在对称轴**哪一侧**、从左往右**升还是降** | 无（非数值题，不硬凑数） |
| 奇偶性 | 新板 `quadratic-parity`（`CAP_TYPE=quadratic`） | 紫色虚线（对称轴）与黑色粗竖线（y 轴）**重不重合** | 无 |

文案原文（`NOTE_INTENT`，读数动作逐条对应画法）：

> **交点个数**：图上的绿色圆点就是抛物线与 x 轴的交点：**数一数有几个绿点**，就是有几个交点。如果整条曲线都在 x 轴上方（或都在下方），一个绿点也没有，那就是没有交点——此时对应的方程无解。拖动 h、k 看交点从两个变成一个、再变成一个都没有。
>
> **单调性**：a = {a}：a > 0 时抛物线开口向上——对称轴左侧曲线从左往右**下降**，右侧从左往右**上升**；a < 0 时正好反过来。图上灰色虚线是它的对称轴，蓝色实线是这条曲线：**题面给的那段曲线落在对称轴哪一侧？从左往右是往上走还是往下走？** 由此读出这一段是增函数还是减函数。
>
> **奇偶性**：是不是偶函数，就看图象关不关于 y 轴对称。图上紫色虚线是这条抛物线的对称轴，黑色竖线是 y 轴：**两条线重合吗？** 重合（对称轴就是 y 轴）时，左右两半沿 y 轴对折能完全重合，f(-x) = f(x)，是偶函数；不重合就不关于 y 轴对称，也就不是偶函数（二次函数不可能是奇函数）。拖动 h 看对称轴离开 y 轴时图象怎么变。

为让「画法 = 文案」，`draw()` 与 `paintModel()` 同步改了三处（描述与绘制必须逐字对应，否则 AI 讲解会指错线）：

1. 讲奇偶性时**额外把 y 轴画成黑色粗实线**（`2.2px`、无虚线），对称轴改**紫色虚线**（`rgba(142,68,173,.95)`）——
   两条线重合与否一眼可辨；`describe()` 同步输出「紫色虚线…黑色粗竖线是 y 轴」；
2. 讲单调性时补一条 `trend` 元素，说明「两侧升降方向相反」；
3. 交点个数题在 `disc<0`（无交点）与「根算得出但落在视野外」两种情况下，`describe()` 明确说
   **图上没有绿色圆点**——不许出现「有两个交点」这类与画面矛盾的描述。

### 13.3 S= 窄门：加了什么、边界在哪

`fromPrompt(prompt)` 拆成薄壳 + `parseCore(s)`（原函数体逻辑一行未改）。薄壳顺序：

1. `direct = parseCore(s)`；**非 `null` 直接返回**（既有 197 道可解析题的输出逐字不变）。
2. 只有 `direct === null` 且题面命中 `/(?:^|[^0-9A-Za-z_.])S\s*=/` 时才走面积路径：
   - 先试「`S=` 右边本就是可解析表达式」：`parseCore('y=' + rhs)` —— 这就是「视同 `y=`」的窄别名，
     **仅在 direct 为 null 之后生效**；
   - 再试面积式乘法展开 `expandAreaRhs(rhs)`：只接受「x 乘一个一次式」形

   - 都不成 → `null`。
3. `expandAreaRhs` **只被 `S=` 路径调用**，其它入口一律不经过它。

自测边界（批4 新增单测逐条钉死）：`S=x(10-x)` 与 `S=x(10−x)` → `quadratic(a=-1,h=5,k=25)`；

### 13.4 为什么三次是两个画板（`cubic-parity` / `cubic-extremum`），而不是卡面上的一个 `cubic-curve`

一张卡片只能有一条 `CAPABILITIES.note`。三次题要讲两件不同的事：

- 奇偶性：红色圆点是**曲线与 y 轴的交点**，讲「绕这个点转 180°、左右是否像照镜子」；
- 极值点横坐标：红色圆点是**每个实驻点**，讲「曲线由升转降、由降转升，左右各一个」。

如果合成一块板，一条 note 同时描述「绕交点转 180°」和「两个转折点红点」，必然有一半与画布不符 ——
这正是批2 F1 的漂移缺陷（描述说标了、画布上却没有 / 标的是另一套点）。所以拆成两块：
`CAP_TYPE` 都是 `'cubic'`，共用同一套底座（蓝色实线曲线 + 黑色粗实线 y 轴 + 网格坐标轴），
只按画板名改变红点集合与文案。现在每块板的 `note` / `describe()` 都与 `annotate()` 的绘制逐字对齐：
`cubic-parity` 的 1 个红点、`cubic-extremum` 的 2 个红点，互不冒充。

### 13.5 三条既有断言的改判（没有删除、没有放宽）

批1/批3 有三条断言写的是「三次一律 null」，那是当年没有三次画板的产物。批4 上线三次画板后，
这三条被**改判**而不是删除或放宽：

### 13.6 §1 括号里的「（一次/二次）」为何还在

§1 正文第 3 条的括号「`fromPrompt()` 原样能解析出曲线的有 **83 题**（一次/二次）」是

### 13.7 此绿灯未证明什么

- **(a) 解析/白名单全绿，不等于 LLM 运行时会选对 intent。** 双视口 E2E 是「逐题给定一个正确 intent」
  再驱动画板，等于模拟了一次正确的 LLM 判断；模型在真实题面上会不会把「顶点坐标」判成
  「对称轴」、把「奇偶性」判成别的，本批没有证据。
- **(b) 双视口 E2E 只证明渲染层没坏。** 它证明的是「有像素、无 console error、无横向溢出、
  画布不空白」；不证明这张图对一个学生来说**数学上可读**（刻度够不够、曲线拐点是否落在可视区、
  红点是否被别的元素压住）。
- **(c) S= 别名是白名单之外的通用放宽面。** 它让语料里所有 `S=<可解析表达式>` 的题面都能解析；
  安全性不靠解析器，而靠 `HS_ITEMS` + `Labmatch.verifyParams` 兜底。将来若有题绕过白名单入口、
  直接把 `fromPrompt` 的结果交给画板，这条别名就会成为新的误挂入口。
- **(d) 三次「导数」语境没有闭环证据。** 两块三次画板的 note / NOTE_INTENT 刻意避开
  「导数为零 / 切线水平」措辞（只让学生从图上读转折点与对称），但没有证据证明「不说这几个词」
  就足以让学生把 `f'(x)=0` 与图上标出的点连起来 —— 这是教学设计问题，不是渲染/解析问题。
- **(e) 没有真实课堂 / 用户数据。** 本节所有结论都来自脚本、单测与无头浏览器的合成运行，
  没有一节课、一个学生的真实使用记录。
